# Channel3 live price-match workflow

The storefront uses 19 saved, verified Channel3 footwear records. Each NORTH/01 price is a **simulated merchant selling price**, computed in integer cents from the saved Channel3 reference using a stable product-ID ordering and a 0.97, 1.05 or 1.10 multiplier. The saved observation, merchant URL and timestamp remain unchanged. Simulated SKU stock, sales, returns and cost are not Channel3 data.

On a customer-initiated **Check Prices** click, the server uses `@channel3/sdk` v4.5.0 `products.retrieve({product_id,country:"US",currency:"USD",selected_options})` for the first selected footwear SKU. It passes the saved Channel3 product ID and the selected size/color; no broad search or page-load request occurs. The returned selected variant is checked for explicit conflicts. The server filters out invalid USD prices, used and explicitly out-of-stock offers, deduplicates and sorts by ascending observed product price, and passes at most 20 offers to Meta Agent B. Unknown availability, preorder and backorder remain eligible and labeled. The cheapest eligible observation is the default matching reference. Shipping and mandatory fees remain unknown; these are not independently verified retailer checkout totals.

Agent A analyzes simulated merchant operations concurrently with the Channel3 retrieval. Agent B recommends a commercial decision, but deterministic merchant policy and server-side offer authorization enforce SKU, session, stock, price floor, evidence age, cart amount and PayPal Sandbox amount. Failed lookup or AI analysis leaves original-price checkout available.

Apply `supabase/migrations/202611090001_channel3_live_budget.sql` after earlier migrations. Legacy Google budget tables are retained only to avoid destructive database changes; they are not used. Set server-only `CHANNEL3_API_KEY` (the existing approved credential), `CHANNEL3_EXACT_MAX_REQUESTS_PER_DAY` (default 10), and `CHANNEL3_EXACT_TIMEOUT_SECONDS` (1–20, default 8). Enable `CHANNEL3_EXACT_LOOKUP_ENABLED=1` only after verifying the migration and account request allowance. The lookup uses zero SDK retries and an atomic PostgreSQL daily budget. `APP_ENV=production` and `PERSISTENCE_BACKEND=postgres` are required for live calls. The independent generic fixture/Channel3 provider remains controlled by `PRICE_DISCOVERY_MODE`.

No live Channel3, Meta or PayPal calls are part of automated tests. For manual Sandbox QA, select a shoe size, check prices once, inspect the `channel3_exact_lookup` safe log and budget row, inspect `agentMode` and merchant prices, accept a valid offer, then inspect the server-created Sandbox order amount before any optional human-approved Sandbox payment. Never use PayPal Live for this demo.
