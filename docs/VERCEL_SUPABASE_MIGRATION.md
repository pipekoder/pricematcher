# Vercel app migration (keep Supabase)

This moves only the Next.js application. Keep Render running until the Vercel deployment is verified. Do not connect Codex to the Vercel account or copy secret values into GitHub, source files, or chat.

1. Confirm GitHub `main` contains the intended release. Vercel's Git integration deploys the production branch automatically; each non-production branch can receive a preview deployment. Do not import the repository until you are ready for the first deployment.
2. In the separate Vercel account, import `pipekoder/pricematcher` from GitHub. Choose root directory `./`, the Next.js preset, and default build/output settings. The Render-only `render.yaml` is ignored.
3. In Vercel Environment Variables, configure **Production** values before the first deployment. Copy secrets directly from the existing Render/Supabase settings, not from this repository. Required for the shared app: `APP_ENV=production`, `PERSISTENCE_BACKEND=postgres`, `DATABASE_URL`, `PRICE_MATCHER_SESSION_SECRET` (at least 32 characters), `DATABASE_SSL=require`, and `DATABASE_SSL_REJECT_UNAUTHORIZED=true`. Reuse the existing session secret if continuity matters. Use the existing Supabase Session pooler connection on port 5432; set `DATABASE_POOL_MAX=1` initially to limit per-function connections. If Render uses `DATABASE_SSL_CA_BASE64`, copy that value too. Do not weaken TLS verification to fix a connection failure.
4. Start safely with `PRICE_DISCOVERY_MODE=fixture`, `PAYPAL_ENVIRONMENT=SANDBOX`, `PRICEMATCHER_DEMO_ASSUMPTIONS=0`, and `AI_OFFER_AGENT_ENABLED=false`. Add `MERCHANT_DEMO_ACCESS_TOKEN` (24+ characters) if the protected merchant operations page is needed. Add PayPal Sandbox and Meta Model API server-only keys only when testing their flows. Never put secrets in `NEXT_PUBLIC_*` variables.
5. Ensure the existing Supabase database has all four migrations in `supabase/migrations/` applied in order, including `202610260001_ai_offer_budget.sql`. Do not rerun migrations blindly on a live database. No database copy is needed when keeping the same Supabase project.
6. Deploy and check `/api/health`, the storefront, bag, original-price and offer flows, protected merchant route, and PayPal Sandbox order creation with mocks or a controlled manual Sandbox QA. The live Meta Model API and PayPal flows must not be claimed verified from build success alone. The AI comparison function bundles the `agents/**/*.md` runtime instructions through `next.config.ts`.
7. After Vercel supplies the canonical HTTPS URL, set `NEXT_PUBLIC_APP_URL` to it if needed, then redeploy. If moving a custom domain, switch DNS only after verification. Retire Render last.

Vercel secrets should be scoped to the environment that needs them. Avoid granting a preview deployment access to the production Supabase database or PayPal credentials. Keep `DATABASE_URL`, session secret, merchant token, and provider keys server-only.
